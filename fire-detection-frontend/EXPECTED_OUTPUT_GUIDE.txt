4. DATA FLOW - How Information Moves Through System
================================================================================

### INITIALIZATION FLOW (Page Load)

Step 1: Browser loads http://localhost:8080
└─ HTML parsed (index.html)

Step 2: CSS loaded (style.css)
└─ All styles applied to page

Step 3: JavaScript loads as ES Module (script.js type="module")
└─ Imports start executing

Step 4: Services imported
└─ src/config.js loaded → Configuration initialized
└─ src/adapters/mockAdapter.js loaded → Mock data ready
└─ src/adapters/apiAdapter.js loaded → API adapter ready
└─ src/services/eventsService.js → Event fetching ready
└─ src/services/predictionService.js → ML prediction ready
└─ src/services/statisticsService.js → Stats ready
└─ src/services/satelliteService.js → Satellite data ready

Step 5: Main script initialization
└─ Initialize map (Leaflet)
└─ Load events: const events = await eventsService.getEvents()
└─ Create markers for each event
└─ Select first event (Pune) by default
└─ Update right panel with Pune details
└─ Render land cover chart for Pune
└─ Fetch and display satellite data for Pune

6. ERROR SCENARIOS - What If Something Goes Wrong
================================================================================

### ERROR 1: PYTHON NOT RUNNING (Batch file issues)

USER ACTION: Double-clicks run_stage3_demo.bat

BATCH OUTPUT:
[ERROR] Python is not installed or not in PATH
Please install Python from: https://www.python.org/downloads/
Make sure to check "Add Python to PATH" during installation

USER SEES: Batch window closes or shows this error

SOLUTION STEPS:
1. Install Python from python.org
2. During installation, CHECK "Add Python to PATH"
3. Restart command prompt
4. Try batch file again


### ERROR 2: PORT 8080 ALREADY IN USE

USER ACTION: Double-clicks run_stage3_demo.bat

BATCH OUTPUT:
[WARNING] Port 8080 is already in use
Enter alternative port (default 8000): _

USER ACTION: Types "8000" and presses Enter

THEN:
- Server starts on http://localhost:8000/
- Batch shows: "Local URL: http://localhost:8000/"
- User opens that URL in browser


### ERROR 3: FILE NOT FOUND

USER ACTION: Runs batch file from wrong directory

BATCH OUTPUT:
[ERROR] index.html not found in current directory
Please run this batch file from the project root directory

SOLUTION:
1. Extract ZIP to folder
2. Navigate to that folder
3. Run batch file from that location (where index.html is)


### ERROR 4: JAVASCRIPT ERROR (Browser console)

USER ACTION: Loads page, something breaks

BROWSER CONSOLE (F12 → Console tab):
Uncaught TypeError: Cannot read property 'getEvents' of undefined
    at script.js:45

MEANING: Service import failed

SOLUTION:
1. Check browser console for red error messages
2. Verify all files exist in src/ folder
3. Try hard refresh (Ctrl+Shift+R)
4. Try different browser


### ERROR 5: MAP NOT SHOWING

USER ACTION: Page loads but map is blank/gray

POSSIBLE CAUSES:
- Network issue (can't load OSM tiles)
- Leaflet not loaded
- No markers created

CHECK:
1. Open browser console (F12)
2. Look for errors
3. Try hard refresh (Ctrl+Shift+R)
4. Check internet connection
5. Try different browser or incognito mode


### ERROR 6: DARK MODE NOT PERSISTING

USER ACTION: Enables dark mode, closes browser, reopens, still light

CAUSE: localStorage disabled or blocked

SOLUTION:
1. Check browser settings (privacy)
2. Allow localStorage for localhost
3. Try different browser
4. Try incognito mode


### ERROR 7: SETTINGS NOT SAVING

USER ACTION: Fills in API URL, clicks Save, goes back to Settings, URL is gone

CAUSE: localStorage not working or not implementing save properly

SOLUTION:
1. Open browser console (F12)
2. Type: localStorage.getItem('config')
3. If returns null, localStorage is not working
4. Try different browser
5. Check browser permissions


### ERROR 8: CANNOT CONNECT TO REAL API (When demo mode disabled)

USER ACTION: Disabled demo mode, API is not running

APP STATE:
- Map shows (no error)
- Right panel shows error or empty state
- No markers appear
- Console shows: Failed to fetch from http://your-api.com

MEANING: System tried real API and it failed, fell back gracefully

SOLUTION:
1. Start your real API server
2. Make sure URL is correct
3. Enable demo mode again if needed
4. Or keep watching for API to start
